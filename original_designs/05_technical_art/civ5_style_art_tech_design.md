# 文明5风格技术美术设计圣经 (Civ5-Style Art & Technical Design Bible)

> **服务对象**：《Project Chronos》战役层原型（崤函 40×30 六边形地图，见[洛阳六边形地图生成器](../../maps/README.md)）
> **目标引擎**：Godot 4.x（推荐 4.3+）
> **风格对标**：Sid Meier's Civilization V（2010, Firaxis / Mels Virtuos 外包美术）
> **文档职责**：连接美术与开发的桥梁——所有视觉效果的**技术实现方案 + 资产预算 + 管线规范**，一次定稿，避免美术返工。

## 一、文明5 视觉风格解构 (Style Breakdown)

要"对标"，先要拆解。文明5 的画面由以下七个视觉支柱构成，每个支柱对应本方案的一节技术设计：

| # | 视觉支柱 | 观感描述 | 对应章节 |
| :--- | :--- | :--- | :--- |
| 1 | **手绘风格化写实地形** | 草原/丘陵/山地有明显笔触感贴图，非照片纹理；色调统一、饱和度克制 | §3 地形 |
| 2 | **六边形秩序感** | 格子边界清晰但不刺眼；高度分层 + 竖直悬崖侧壁；河流沿格边流淌 | §3 / §4 |
| 3 | **柔和全局光** | 几乎无硬阴影边；"太阳斜照 + 天光补光"的烘焙感；云影缓慢扫过地面 | §7 氛围 |
| 4 | **三态战争迷雾** | 未探索=纯黑遮罩；已探索=半透明暗纱（记忆态）；可见=全亮 | §5 迷雾 |
| 5 | **高辨识度领土边界** | 文明色发光边界沿格子边缘描线，河流/关隘处尤其清晰 | §6 边界 |
| 6 | **低模手绘单位** | 单位是低面数模型 + 手绘贴图 + 明确剪影；选圈/血条/旗帜信息层永远干净 | §8 单位 |
| 7 | **克制的后期** | 轻 bloom、轻色偏、几乎没有动态模糊；UI 平面化、留白多 | §9 后期 |

**一句话风格宪法**（美术与开发共同遵守）：

> 地形负责"美"，六边形负责"秩序"，迷雾负责"氛围"，单位负责"信息"。
> 任何让格子边界变得模糊、让单位变得喧宾夺主的视觉方案，一律否决。

### 1.1 与《Project Chronos》的本地化嫁接

文明5 是全球随机地图，我们是**崤函古战场**——风格对标其"支柱"，素材气质则应转向中国水墨式手绘（参照《全面战争：三国》地形 + 文明5 的格子秩序）。技术方案完全不变，只替换贴图资产与色彩分级 LUT。

## 二、引擎与渲染管线选型 (Engine Pipeline Decision)

| 选项 | 结论 | 理由 |
| :--- | :--- | :--- |
| **Godot 4 Forward+** | ✅ **主选**（PC 目标） | Vulkan，支持 compute、SDFGI/VoxelGI、3D 纹理、实例化剔除；策略游戏视角固定俯视，光照简单，Forward+ 完全跑得动 |
| Godot 4 Mobile | ⚠️ 备选（若未来上 Steam Deck/掌机） | 本方案所有 shader 均提供 mobile-safe 写法（见各节标注） |
| Godot 4 Compatibility (GL3) | ❌ 不选 | 无 compute、无 SDFGI；数据纹理方案可跑但过斑驳，画质上限低 |
| Unity URP / Unreal | ❌ 不选 | 项目已定 Godot；策略游戏对引擎特效上限需求不高，Godot 工作流更轻 |

**关键架构决策——数据纹理驱动的地形渲染 (Data-Texture-Driven Terrain)**：

传统做法是每种地形一个材质、每格一个 Mesh（draw call 爆炸）。本方案改为：

```
游戏逻辑（GDScript，每回合更新）
    │  写入 40×30 RGBA8 ImageTexture（"网格数据纹理"）
    │    R = 地形类型(0-255)   G = 迷雾状态(0/128/255)
    │    B = 领土归属(文明色索引)  A = 变化遮罩(河流/道路/悬崖位)
    ▼
单个合并地形 Mesh + 1 个超级 shader
    │  逐像素采样数据纹理 → 决定贴图混合、迷雾、边界发光
    ▼
GPU 一次性完成所有视觉判定
```

- **Draw call**：整张地图地形 = **1 个 draw call**（含迷雾与边界，无需任何后处理 pass）
- **CPU 开销**：每回合迷雾/领土变化 = 重写一张 40×30 的小贴图（<0.1ms）
- **代价**：shader 复杂度前置（一次写好，全项目复用）；地形贴图需做成 **Texture2DArray**

> 本方案同样适用于大规模地图（如未来 128×96）：数据纹理随网格等比放大，draw call 恒为 1。

## 三、六边形地形渲染 (Hex Terrain)

### 3.1 网格构建

- **格子几何**：点顶六边形（pointy-top，与[地图生成器](../../maps/gen_luoyang_map.py)一致），边长归一化为 1.0 世界单位。
- **高度分层**：平原=0 / 谷地=-0.25 / 丘陵=+0.35 / 山地=+0.8。格子之间的高度差生成**竖直悬崖侧壁**（文明5 的标志性感）。侧壁单独建 mesh，走同一 shader 的"悬崖分支"。
- **合并策略**：`ArrayMesh` + `SurfaceTool` 把全部格子顶面烘焙成一个静态 Mesh；每格顶点 UV 同时记录（a）格子中心在数据纹理中的坐标（custom0），（b）格子内局部坐标 0~1（UV）。
- **装饰物**（树木/岩石/农田）：`MultiMeshInstance3D` 按地形类型批量实例化，接受 GPU 剔除。

### 3.2 地形贴图混合

- 8 种地形类型打包进一张 **Texture2DArray**（每层 512×512，BC7/ASTC 压缩）。
- 每个像素采样**当前格类型贴图** + 依据局部坐标在**格边缘 12% 带宽**内混入邻格类型贴图 → 得到文明5 那种"格子边界处自然咬合"的过渡。
- 采样点法线扰动：贴图混合权重乘以高度差衰减——落差 >1 级时不混合（出现悬崖），落差 ≤1 级时柔和过渡。

### 3.3 河流与道路

- 河流不单独建 mesh：按六条边方向烘焙成**边缘遮罩**（数据纹理 A 通道位运算），shader 中叠加河流贴图条带（流向由边方向决定 UV 旋转）。
- 道路同理，用另一组贴图（泥路/石驿道/驰道三个时代变体）。

### 3.4 实现

完整代码见 [`shaders/terrain_hex.gdshader`](shaders/terrain_hex.gdshader)（含地形混合 + 三态迷雾 + 领土边界 + 云影，四合一）。

## 四、水体 (Water)

黄河、洛水、伊水、涧水。文明5 水体特征：**不透明偏写实、有岸线泡沫、缓慢流动的高光**——不是热带海那种透明清澈。

- 水面 mesh = 地形格子的水面高度 (-0.05) 处再铺一层合并 mesh（仅水面格子）。
- Shader 三要素：
  1. 两层滚动法线（反向速度）产生流动高光；
  2. **岸线泡沫**：采样地形数据纹理判断邻格是否陆地 → 沿水陆交界生成白色泡沫带（宽度随时间轻微脉动）；
  3. 深度渐变色：离岸越远越深（同样由数据纹理距离场近似）。
- 时代氛围：战国乱世黄河水偏土黄 → `water_tint` 参数暴露给美术调色。
- Mobile-safe：泡沫与流动均在 alpha 混合 pass，无折射无深度采样。
- 实现见 [`shaders/water_hex.gdshader`](shaders/water_hex.gdshader)。

## 五、三态战争迷雾 (Fog of War)

文明5 迷雾的三态及对应实现：

| 状态 | 观感 | 数据纹理值 | 实现 |
| :--- | :--- | :--- | :--- |
| **未探索** | 纯黑，带轻微噪点纹理 | G = 0 | 地形贴图直接乘以 0.02 + 星图噪点 |
| **已探索（记忆态）** | 半透明暗纱，地形隐约可见，单位不显示 | G = 128 | 地形乘以 0.45 + 去饱和 70%，装饰物淡出 |
| **当前可见** | 全亮 | G = 255 | 原样渲染 |

- 迷雾判定在**地形 shader 内**逐像素完成（采样数据纹理 + 与本格迷雾值插值），**不叠任何全屏遮罩层**——这保证了文明5 那种迷雾边缘的柔和渐变（在两个格子间做 Hermite 插值）。
- 装饰物（树木等）单独走 [`shaders/prop_fog_fade.gdshader`](shaders/prop_fog_fade.gdshader)：记忆态时整体压暗 + 半透明淡出，避免"黑纱下立着一片树"的违和。
- 单位由逻辑层控制（迷雾格内单位不实例化），不走 shader。
- **移动性提示**：选中单位时，可到达范围 = 逻辑层算好后写进数据纹理另一个位，shader 叠加白色呼吸光圈。

## 六、领土边界 (Territory Borders)

文明5 边界的秘诀：**文明色 + 边缘描线 + 微光晕 + 内侧渐隐**。

- 数据纹理 B 通道 = 领土归属索引（0=无主，1..N=文明）。
- Shader 逐像素比较当前格与邻格（上/下/左/右采样数据纹理）的归属值：
  - 不同 → 该像素处于边界上 → 绘制文明色描线（宽度 ~0.06 格）；
  - 同属且非本主 → 内侧 0.3 格宽度做文明色 8% 透明度渐染（文明5 的"国家底色"）。
- 文明色查找表：一张 256×1 的渐变纹理，B 通道直接当 UV 索引 → 增加文明零 shader 改动。
- 边界线加一层 `sin(time)` 微呼吸（振幅 0.05）——文明5 后期版本的经典细节。

## 七、环境氛围：云影与光照 (Lighting & Cloud Shadows)

- **主光**：`DirectionalLight3D`，角度 55°/35°，暖白（色温 ~5800K），**开启软阴影**（PSSM 4 splits，blend 0.6）——文明5 的柔和影感靠大 blend 值。
- **环境光**：`WorldEnvironment` 用 `ProceduralSkyMaterial`，能量 0.6；不用 SDFGI（策略俯视角收益低、性能代价高），改为美术在贴图里烘焙 AO。
- **云影**：地形 shader 中叠加两层滚动 Perlin 噪声（不同速度反向），输出为光照乘数 0.85~1.0——即"云缓慢扫过战场"，纯 shader 零成本。风向参数化（西北风：vec2(-0.7, 0.3)）。
- **时代色调**：`Environment` 的 color correction 挂 LUT，春秋/战国/秦统三张 LUT 渐变切换（配合 §10 的时代演进特效）。

## 八、单位表现 (Units & Selection)

文明5 单位是"棋子"而非"角色"——信息优先、动效克制。

| 要素 | 预算/方案 |
| :--- | :--- |
| 模型 | LOD0 ≤ 6,000 tris / LOD1 ≤ 2,500 / LOD2 ≤ 800（俯视角基本只用到 LOD1） |
| 贴图 | 512×512 albedo（手绘，含简单 AO）+ 256×256 蒙版，BC7；**同一兵种多文明复用模型，只换旗帜/服色 mask** |
| 动画 | 待机(idle 2 种循环) / 移动(走跑合一) / 攻击(单次) / 死亡(倒地+溶解)，共 ≤ 4 组 |
| 选圈 | 贴地 quad + [`shaders/unit_selection.gdshader`](shaders/unit_selection.gdshader)：旋转双环 + 呼吸亮度 + 移动范围高亮复用 |
| 剪影 | 美术规范：单位主体色 3 阶明度对比，顶视角 45° 剪影测试必须一眼可辨兵种 |
| 血条/状态 | 2D overlay（`Sprite3D` + billboard），不进 shader |
| 时代演进 | 单位贴图不变，武器部件替换（`BoneAttachment3D` 挂点）+ 全局时代色调 LUT |

**单位溶解消亡**：战斗死亡动画用 alpha-clip 噪声溶解（参照文明5 单位撤退/死亡的尘化），已在选圈 shader 同文件中附变体思路。

## 九、后期与色彩分级 (Post-Processing)

文明5 后期的克制是风格的一部分——**总量控制在 2ms 内**：

| Pass | 参数 | 预算 |
| :--- | :--- | :--- |
| Glow | intensity 0.4, threshold 0.9, soft | 0.5ms |
| Color Correction | LUT（春秋暖/战国冷/秦统金铜） | 0.3ms |
| Vignette | 轻（0.15） | — |
| SSAO | **不开**（贴图烘焙 AO 替代） | 0 |
| DoF | 仅领袖/事件特写场景开 | 场景级 |
| TAA | 开（策略相机移动缓慢，无鬼影风险） | 0.5ms |

UI 风格：文明5 式平面深色面板 + 描金细线 + 大量留白；字体衬线（思源宋体）。UI 走 Godot `Control` 体系，不进 3D 渲染。

## 十、标志性特效清单 (Signature VFX)

按优先级排序，前 3 项为原型期必做（"文明5 感"的最低配置）：

1. **回合切换涟漪**：End Turn 后以首都为中心一圈文明色涟漪扫过（数据纹理变化遮罩驱动，地形 shader 内实现，零额外粒子）。
2. **关隘烽火**：函谷关/虎牢关被攻击时狼烟粒子（SpriteParticle，additive，单系统 ≤ 64 粒子，2 层 overdraw）。
3. **战斗尘暴**：近战碰撞点扬尘（贴地烟雾 billboard，alpha blend，≤ 120 粒子）。
4. 时代演进转场（全屏 LUT 渐变 + 单位集体溶解重组）。
5. 城市成长粒子（人口+1 时民居模型 pop-in 弹跳 + 尘土）。

所有粒子遵守：**单效果 overdraw ≤ 3 层，纹理进共享 atlas（256×256/格），优先 alpha-clip**。

## 十一、资产技术预算总表 (Asset Budgets)

### 地形贴图（Texture2DArray）

| 项目 | 规格 |
| :--- | :--- |
| 单层分辨率 | 512×512（可平铺） |
| 地形层数 | 8（平原/谷地/丘陵/山地/雪顶/沙漠/河流带/道路带） |
| 压缩 | BC7(PC) / ASTC 6×6(Mobile) |
| 装饰物贴图 atlas | 1024×1024，16 格，ASTC 4×4 |

### 单位

| LOD | Max Tris | 贴图 | Draw Calls |
| :--- | :--- | :--- | :--- |
| LOD0（事件特写） | 6,000 | 512² | 2 |
| LOD1（战场） | 2,500 | 512²（共享） | 1 |
| LOD2（远景） | 800 | 256² | 1 |

同屏单位上限：**64 个兵种单位 + 40 个装饰 MultiMesh 批次**。

### 场景整体预算（GTX 1060 / 1080p 基准）

| 项目 | 预算 |
| :--- | :--- |
| 总 draw calls | ≤ 120 |
| 地形+水面+装饰 | ≤ 6 draw calls |
| 帧时间 | 16.6ms 中渲染占比 ≤ 8ms（策略游戏逻辑同步大开销预留） |
| 显存贴图总量 | ≤ 256MB |

## 十二、资产管线规范 (Asset Pipeline)

1. **命名**：`sm_unit_{era}_{type}_{civ_variant}`（如 `sm_unit_zhanguo_infantry_qin`）、`sm_terrain_grass_l1`；贴图后缀 `_albedo/_mask`。
2. **导入预设**：Godot `.import` 由技术美术统一出 preset 文件，美术**禁止手改**导入设置。mipmap：世界贴图开 / UI 关；normal map 走 normal 压缩预设。
3. **DCC 交接**：Blender/FBX 导出前跑校验脚本（pivot 在格中心、scale=1、UV 无重叠、法线朝外）；烘焙贴图统一 sRGB albedo / linear mask。
4. **验收流程**：所有资产必须进 `review_map.tscn`（生产光照 + 崤函地图裁片）在**游戏相机角度**下验收，DCC 截图不算数。
5. **色板纪律**：地形色板由技术美术锁定（见 `terrain_palette` 参数），美术贴图必须从色板取色——这是文明5"色调统一"的真正秘密，比任何后期都重要。
